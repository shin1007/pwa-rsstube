# どのサイトの本文が取れるか（110サイト実測）

2026-08-15 実施。各サイトのトップから実際の記事URLを1本見つけ、**本番と同じ
`extractArticle`**（`/api/debug/extract`）に通した結果。推測ではなく実測値。

## 結論

| 分類 | 数 | 取れた | 取れない |
|---|---|---|---|
| 日本の省庁 | 20 | 16 | 1 |
| 日本の自治体 | 20 | 18 | 0 |
| 海外政府 | 20 | 14 | 2 |
| 人気サイト（日本） | 25 | 24 | 0 |
| 人気サイト（海外） | 25 | 18 | 6 |
| **計** | **110** | **90** | **9** |

残り11件は調査スクリプトのURL探索が失敗しただけ（後述）。

**取れない9件はすべて「本文が読めない」のではなく「そもそも接続を拒否される」。**
Readability も文字コード判定も関係ない。

> **2026-08-26 追記。** この「サイト単位」の見方だけでは足りなかった。
> 実際に購読しているフィードの**記事単位**で数え直すと、失敗の6%は
> 一度きりの失敗で、いま叩けば取れる。下の「記事単位で数え直した（2026-08-26）」を参照。
> Aeon がその代表で、ここでは 429（流量制限）と記録されている——
> つまり**この表の時点で既に「そのうち戻る」型だと分かる情報が載っていた**。

## 取れないサイト（9件）

いずれも **403 / 401 / 429 を返す**。ブラウザと同じ User-Agent でも同じ結果なので、
UA ではなく IP か TLS 指紋で弾いている（Akamai / Cloudflare / DataDome 系）。
こちらの実装では直せない。

| サイト | 症状 | 種類 |
|---|---|---|
| 防衛省 | 403 | ボット遮断 |
| 仏首相府 (info.gouv.fr) | 403 | ボット遮断 |
| ノルウェー政府 (regjeringen.no) | 403 | ボット遮断 |
| Reuters | 401 | 有料＋遮断 |
| NYTimes | 記事本体が 403 | 有料 |
| WSJ | 401 | 有料 |
| Bloomberg | 403 | 有料＋遮断 |
| Science (science.org) | 403 | 有料 |
| Medium | 記事本体が 403 | ボット遮断 |
| Aeon | 429 | 流量制限 |

Aeon の 429 は待てば通る可能性がある（巡回間隔が1時間なら実運用では出にくい）。
それ以外は、**フィードのタイトルとリンクだけ取り込み、本文は元サイトで読む**という
現状の挙動で妥協するしかない。要約も付かない。

## 判定できなかった11件（調査側の都合）

トップページから記事URLを推定する部分が失敗しただけで、サイト自体は 200 を返す。
実フィードを登録すれば取れる見込み。

- **リンク推定が索引ページを掴んだ**（本文が数十字しか無い）:
  特許庁(62字) / 京都府(50字) / 広島市(35字) / 韓国政府(55字) / ブラジル政府(69字)
- **記事URLが見つからなかった**: こども家庭庁 / 台湾行政院

  - NHK は実フィード (`www3.nhk.or.jp/rss/news/cat0.xml`) 経由で **3348字取れた**。問題なし。
  - 気象庁の防災情報フィードは中身が **XML（気象庁独自形式）** で HTML ではない。
    本文抽出の対象外。取り込むなら専用の変換が要る。
- **Nature**: 記事は 200 で取れるが **209字**（アブストラクトのみ、本文は有料）。

## 政府・自治体サイトの追試（2026-08-15）

「RSSが渡してくる中身」と「実際のページから取れる本文」を、**アプリ本体の
`discoverFeeds` / `fetchFeed` / `extractArticle` を通して**突き合わせた20サイト。

### 文字化けは1件も無かった

タイトル・RSSの抜粋・本文のいずれにも化けは出ていない。**Shift_JIS の総務省でも
タイトルは正しい日本語で取れる**（`parse.ts` がフィードも `decodeBody` に通しているため）。

なお、検証を rss-parser の `parseURL` で書いたときは総務省のタイトルが化けた。
**あれはライブラリが charset を見ないから**で、アプリの経路とは別物。
「化けた」と報告が来たら、まずどちらの経路の話かを確かめること。

### フィードが見つからない問題（直した）

20サイト中16で「フィードが見つかりません」になっていた。原因は
**官公庁・自治体がトップに `<link rel="alternate">` を置いていない**こと
（素の正規表現で数えてもゼロ。告知していないだけでフィードは在る）。

当てずっぽうで叩く場所が `/feed` `/rss` などブログ向けばかりで、日本の官公庁が
使う **RSS 1.0（`.rdf`）** が入っていなかった。さらにリストに6件書いてあるのに
**先頭4件しか試していなかった**（`MAX_GUESSES`）。

`.rdf` を足し、全部を並行で叩くようにして 4件 → 7件 に増えた:

| サイト | 見つかった場所 |
|---|---|
| 総務省 | `/news.rdf` |
| 国土交通省 | `/index.rdf` |
| 東京都 | `/rss/index.rdf` |

残りは総当たりでも当たらない（フィードが下層ページにしか無い）。
**URL を直接貼れば登録できる**ので、機能としては詰んでいない。

### そのほか気づいたこと

- **総務省のフィードは死んだURLを指していた**（記事が 404）。こちら側の不具合ではなく、
  `ok: false` として正しく記録されている
- **札幌市は本文132字**。ページ自体が「更新しました」だけの告知で、中身は別ファイル
- 海外政府（ホワイトハウス・GOV.UK・EU・国連・カナダ）はトップから辿れない。
  いずれもフィードは持っているので、URL を直接貼る運用になる

## 自治体と海外政府 122サイト（2026-08-15）

日本の47都道府県・主要25市区・海外政府25・海外自治体25を、アプリ本体の
`discoverFeeds` → `fetchFeed` → `extractArticle` に通した。

### 文字化けはゼロ

122サイトのどこにも化けは無かった。**Shift_JIS・EUC-JP のサイトも正しく読める。**

> 検証の途中で10件が「化け」と出たが、**全部こちらの判定関数の不具合**だった。
> 文字範囲を `U+0080`〜`U+00FF` のつもりで書いたのに空白（`U+0020`）から始めていて、
> ASCII 全部を化け扱いしていた。実際のタイトルは `Statement by President Meloni` の
> ように正常。**「化けている」と出たら、まず判定側を疑うこと。**

### フィードを見つけられるか（ここを直した）

| | サイト数 | フィード発見 | 本文まで |
|---|---|---|---|
| 日本の都道府県 | 47 | 10 → **18** | 15 |
| 日本の市区 | 25 | 7 → **12** | 12 |
| 海外の政府 | 25 | 4 | 4 |
| 海外の自治体 | 25 | 6 | 4 |
| **計** | **122** | 27 → **40** | **35** |

見つかったフィードのURLを眺めると、日本の自治体は
**ディレクトリ名とファイル名を繰り返す**形が圧倒的に多い
（`/shinchaku/shinchaku.xml`、`/chumoku/chumoku.xml`）。
未発見の55サイトに候補パスを当てたところ、当たりはこうなった:

| パス | 当たり |
|---|---|
| `/shinchaku.xml` | 9 |
| `/shinchaku/shinchaku.xml` | 7 |
| `/topics.xml` | 3 |
| `/chumoku/chumoku.xml` | 2 |
| `/main/rss/rss.xml` | 2 |

これらを `COMMON_PATHS` に足して 27件 → 40件 になった。

### 残りが見つからない理由

**海外は自動発見がほぼ効かない**（政府25中4、自治体25中6）。トップに
`<link rel="alternate">` を置かず、パスも各国ばらばらで当てようがない。
URL を直接貼れば登録できるので、機能としては詰んでいない。

本文が取れなかった5件: 栃木県・鹿児島県（フィードが**死んだURL**を指している）、
京都府（接続失敗）、ロンドン市・アムステルダム市（403）。
いずれもこちら側の不具合ではない。

## この結果から言えること

1. **一般的な用途では困らない。** ニュース・技術ブログ・官公庁のお知らせは
   ほぼ全部読める。読めないのは有料メディアと、極端に厳しいボット対策のサイト。
2. **有料メディアは諦める。** Reuters / NYTimes / WSJ / Bloomberg / Science は
   購読していても、こちらからは cookie を持たないので本文に届かない。
3. **UA 偽装は無意味だった。** ブラウザの UA でも 403 のままなので、
   小細工をせず正直な UA を名乗り続けるのがよい。
4. **気象庁のような独自XMLは別枠。** 欲しくなったら専用の取り込みを書く。

# 記事単位で数え直した（2026-08-26）

上の110サイトは「サイトのトップから拾った記事1本」を1回だけ試したもの。
本番で**実際に失敗している567件**を叩き直すと、見え方が変わった。

## 結論：3種類に割れる

| 種類 | 件数 | 割合 | 直せるか |
|---|---|---|---|
| 本文がHTMLに無い | 347 | 61% | ✗ |
| 弾かれている | 185 | 33% | ✗ |
| **一度失敗しただけ** | **35** | **6%** | **○** |

### 本文がHTMLに無い — 東洋経済オンライン 347件（そのフィードの81%）

HTTP 200 が返り、HTMLも118KBある。**しかし記事本文はそこに入っていない。**
`<article class="l-article">` の中身は126字（見出しと日付だけ）で、
Readability が掴むのはグローバルメニュー（「有料会員登録 お知らせ ビジネス
政治・経済・投資…」）1,215字。ページには広告ブロッカー検出の文言も入っている。

0016 / 0018 の使い回し判定がこれを正しく弾いている（フィード内で先頭200字が
一致するため）。**判定が働いているので、直っているように見えないだけで正常。**

### 弾かれている — Hacker News 185件（そのフィードの16%）

HN の記事URLは第三者のサイトを指す。実測で 403（nytimes・medium・wiley・
dl.acm.org）、401（reuters）、または JS でしか描かれないページ（0字）。
**HN 自体は正常**で、リンク先の性質の問題。

### 一度失敗しただけ — 35件

| フィード | 件数 | いま叩き直すと |
|---|---|---|
| Aeon | 21 | **15,000〜25,000字の本文が返る** |
| ダイヤモンド・オンライン | 8 | 800〜3,600字 |
| NHKONEニュース | 3 | 取れる |
| ライフハッカー・ジャパン | 3 | 取れる |

Aeon は上の110サイト表で **429（流量制限）** と記録されている。つまり
「そのうち戻る」型だと分かる情報が最初からあった。

問題は仕組みのほうだった。`extracted_at` が入った時点で「処理済み」になり、
**取れなかった記事は二度と取りに行かない**。相手の一時的な不調・公開直後の
CDN・20秒のタイムアウトで落ちたぶんが、そのまま永久に「本文なし」で残る。

`0028` で理由（`extract_fail`）を残し、`network` と `short` のときだけ
6時間後に1回だけ取り直すようにした。`recycled`（東洋経済）と `blocked`
（Hacker News）は取り直さない——毎日20件ぶん、何も変わらない取得を
繰り返すことになるため。

## この数え直しでやったこと

- 失敗している記事から、フィードごとに散らして55件を抜き、本番と同じ UA で再取得
- HTTPステータス・HTMLの大きさ・Readability の結果を記録
- **「長さがあれば成功」で数えないこと。** 最初に長さだけで数えたときは
  「76%が取り直せる」という答えが出たが、中身を見たら東洋経済のメニュー1,215字を
  「取れた」と数えていた。判定は必ず中身を見る

## 複数ページに割れる記事（2026-09-30、著名73サイトの直近3記事ずつ）

記事の**本文そのもの**が `/2` や `?page=2` に割れているサイトを探した。1ページ目しか
取れないと、途中で切れた本文が「取れた」ことになって要約に回る。

| サイト | ページ送りの形 | 対応 |
|---|---|---|
| Nazology | `/archives/ID/2` | 済（`findPagerNext`） |
| ITmedia（PC USER・@IT など） | `news079_2.html`、`rel=next` | 済 |
| ASCII.jp | `/4436699/2/`、`rel=next` | 済 |
| 日経xTECH | `?P=2`、`rel=next` | 済（大文字の P も見る） |
| プレジデントオンライン | `?page=2` | 済 |
| 文春オンライン | `?page=2`（`<a>` が複数行に渡る） | 済 |
| 現代ビジネス | `?page=2` | 済 |
| Phoronix | 複数ページで有名 | **確認できず**（403） |

- GIGAZINE は「次のページ」の文字にだけ反応した**誤検出**（前後の記事へのリンク）。単ページ。
- ITmedia NEWS・PC Watch・Gizmodo・Verge・Ars・Guardian・BBC・Wired など、
  残りの約55サイトは直近3記事にページ送りが無かった。
- 取得できなかった: Forbes・The Atlantic・Economist・Fast Company・PCMag・HBR（403/遮断）、
  ダイヤモンド・ねとらぼ・Space.com・Digital Trends（フィードからリンクが取れず）、
  Impress Watch・CNET Japan・ZDNet Japan・Real Sound・読売（フィードURLが404）。
  ここは調査の都合で、ページ送りが無いという意味ではない。
- 辿る条件は「いまのURLと同じ記事の芯で、番号が1つ大きい」だけ（文字は見ない）。
  `rel=next` も芯が違えば採らない。上限10ページ。
